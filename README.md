# taxi-monitor

Userbot на **вашем аккаунте Telegram** (MTProto/Telethon, без Bot API).
Слушает чаты такси, куда добавлен аккаунт, находит заказы и складывает их
в отдельный приватный канал **«🚕 Заказы такси»** (создаётся автоматически).

Формат сообщения в канале:

```
🚕 Новый заказ
Источник: Такси Город

<ровно тот текст, что написали в чате>
```

> Боты не имеют доступа к содержимому произвольных чатов. Поэтому здесь
> работает именно userbot: аккаунт должен состоять в чате, и тогда он видит
> всё, что видит обычный участник.

## Установка на сервер (Ubuntu/Debian)

```bash
# 1. Создать каталог и залить файлы
mkdir -p /opt/taxi-monitor
# (залить run.py, triggers.py, config.py, store.py, tools/, deploy/)

cd /opt/taxi-monitor
python3 -m venv .venv
.venv/bin/pip install -U pip
.venv/bin/pip install -r requirements.txt

# 2. Настроить .env
cp .env.example .env
nano .env          # API_ID, API_HASH
```

### Где взять API_ID / API_HASH
1. Откройте https://my.telegram.org → войдите по номеру телефона;
2. «API development tools» → создайте приложение (название любое);
3. Скопируйте `api_id` и `api_hash` в `.env`.

Это **не токен бота** — это доступ к вашему аккаунту. Никому не передавайте.

### Вход в аккаунт
```bash
.venv/bin/python tools/login.py
```
Введите телефон, код из Telegram, пароль 2FA (если есть). Скрипт напечатает
строку `SESSION_STRING=...` — вставьте её в `.env`.

> Вход выполняется один раз. Дальше сервис работает на сохранённой сессии.

### Запуск
```bash
cp deploy/taxi-monitor.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now taxi-monitor
journalctl -u taxi-monitor -f
```

Сообщения в канале дают обычный пуш на телефон. Заголовок и строку-источник
можно отключить (`NOTIFY_HEADER=`, `INCLUDE_SOURCE=false`), тогда останется
ровно текст заказа.

## Управление (пишите в «Избранное» самому себе)

| Команда | Действие |
|---|---|
| `/status` | состояние и статистика |
| `/chats` | список отслеживаемых чатов |
| `/add @chat` | добавить чат (или `t.me/+invite`, или ID) |
| `/del @chat` | убрать чат |
| `/test текст заказа` | проверить триггеры, ничего не отправляя |
| `/id` | ID текущего чата |
| `/help` | справка |

Для приватной группы по инвайт-ссылке сначала вступите в неё обычным
аккаунтом, потом `/add https://t.me/+...`.

## Триггеры

Скор = **2 × сильные триггеры + 1 × структурные признаки**. Порог `MIN_SCORE`.
Стоп-слова (вакансии, аренда, продажа, реклама) отбрасывают сообщение сразу.

**Сильные:** «заказ», «заявка», «нужна машина/такси», «кто свободен»,
«есть работа», «подача к/на», «клиент ждёт», «передам заказ», «трансфер»,
«межгород», «срочно такси» …

**Структурные:** телефон, адрес (ул./пр-т/д./кв.), время («через 10 мин»,
«к 14:30», «сейчас»), цена («350₽», «наличные/безнал/фикс»), маршрут
(стрелка или «от … до …»), пассажиры/детали.

**Стоп-слова:** «ищу работу», «требуются водители», «вакансия», «сдам авто»,
«аренда», «продам», «запчасти», «ремонт», «реклама», «обучение» …

Проверить на примерах:
```bash
.venv/bin/python tools/test_triggers.py
```

## Антидубли и антифлуд
- одинаковый по смыслу текст (без цифр/пунктуации) не уходит повторно
  `DEDUPE_TTL` секунд (по умолчанию 15 минут);
- между отправками пауза `SEND_DELAY` (по умолчанию 1.5 с).

## Безопасный прогон
`DRY_RUN=true` — находит заказы, но только пишет в лог. Рекомендуется
на первые сутки теста.
